## Actual-main executable checks

Only `subprocess.run` at the real release-builder `stage` boundary is instrumented. Existing native validators/readers, admission, recipe loader, runtime identity and history/dependence readers are not patched. Git calls and the actual configured-interpreter metadata probe remain real. Any other child process fails the exam.

The planning call must return success with zero stage children. The execute call must reach ledger exactly once, with the candidate entrypoint, explicit Python, selected recipe, output root, workspace-derived `dataPortfolio`, retained cache and workbook descriptor. The boundary returns named `D414_EXAM_FIRST_STAGE_STOP` exit97; main must return nonzero and start no later child. Same-identity resume may retry that failed first child. Changed resume identities must stop beforehand.

Prepared negatives cover missing/invalid extension schema, missing source/recipe/receipt, changed recipe/contract hashes, history mismatch, retained producer B selected against A, wrong epoch binding, omitted panel, invalid predecessor file, create-only collision with preserved sentinel, bad date/runtime/repo/Python, overlapping output/portfolio roots, and changed resume date/source/runtime. Coherent recipe variants update the outer artifact definitions, so inner native reader failures cannot be replaced by an accidentally stale recipe hash. Retained producer B is an actual prior generation, not invented financial data.

Candidate PASS means only `PASS_NATIVE_INITIAL_PREFLIGHT_AND_FIRST_STAGE_ROUTING_ONLY`. The candidate path has not run yet because the implementation is absent. The preparation path passed baseline native prereads; the `--rebuild` branch is supplied for parent-controlled candidate verification and has not been redundantly executed on unchanged baseline code.
